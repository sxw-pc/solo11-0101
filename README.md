# 雨量站采录台

纯本地证据采集与业务决策工具。输入为虚构 fixture，运行中不访问网络。Python 3.11+ 标准库为运行依赖，pytest 为测试依赖。

## 快速开始

`python -m pip install . --no-build-isolation --no-deps` 在本地安装已预装构建工具的环境中构建此项目；运行期无第三方依赖。

`python -m rainstation demo` 自动初始化临时工作区、导入 fixture、计算决策并打印报告路径。`python -m rainstation --help` 查看手动导入、复核及报告命令。`python -m pytest -q` 运行自动化测试。

## 外部设备披露与内部证据隔离

内部审计报告（`report`，仅 `--role internal-auditor`）保留完整采录证据：`event.payload`、`source.path`、原始行与单站设备型号。外部设备供应商不持有该角色，调用即被 `PermissionError` 拒绝，无法借内部通道绕过。

面向外部受众的汇总走独立的 `publish` 命令，交付文件只含六个白名单字段：授权站点集合、T2 汇总数、发布 ID、批次 ID、规则版本与指标名；不含任何单站型号、设备 ID、载荷、来源路径或可反查地址。发布前把每个站视为二元取值（是否 T2），联立该受众**全部**已发布集合-计数约束，枚举所有可行赋值；只要有单站在全部可行赋值中取值相同（含全零/全一极端与多份重叠的线性联立），即判定可被反推：

- `--policy deny_unsafe`：存在反推风险时拒绝，不写数值文件；
- `--policy minimum_safe_coarsening`：仅从请求声明的 `allowed_expansion` 中按最少站点、同数量字典序加入站点使发布恢复安全；无安全扩展则拒绝。

每次实际发布/拒绝都进入按受众隔离的持久化台账 `disclosure_ledger`（集合、计数、请求/策略、文件 SHA-256、状态）。被拒请求、未授权站点与其他受众的记录不参与本受众的知识检查。同一请求重放返回同一发布或拒绝；同受众并发由进程内受众锁与 SQLite `BEGIN IMMEDIATE` 双重串行化。文件先经临时文件加 fsync 原子改名，台账先记 `pending` 再交付，`reconcile` 命令可在中断后恢复一致：补记或按摘要重建同一文件、清除无台账记录的孤儿文件，摘要冲突时拒绝换文件重发。

## 数据流和约束

配置文件的 SHA-256 冻结到 `meta`；`source` 存每个输入文件的哈希；`event` 存逐行规范化记录和事件身份；`issue` 保存解析或业务问题；`decision` 保存规则版本、业务结论和引用的事件 ID。导入采用单个 SQLite 事务；同文件哈希重入不重复写，同事件身份但不同内容进入冲突队列。业务规则读取事件时间而非文件顺序；未知对象或缺证据不能自动视为正常。决策重算保持源事件不可变。

错误码见 `issue.code`，报告同时输出 JSON 和 Markdown。`fixtures` 中是确定性的全虚构数据。首版只支持单机、单批；配置一旦冻结，变化需新建工作区。细分业务边界与未来方向由项目生成提示词约束，首版没有预置未来功能。
