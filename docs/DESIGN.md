# 雨量站采录台设计

站点契约声明时区偏移、脉冲系数生效时间、最大时钟漂移、物理小时强度与可选相邻站对照。输入脉冲、校时锚点、维护窗口和设备心跳均保留来源文件、行号、事件身份和哈希。

数据流：站点契约 → 原始事件 → 设备序号缺口与锚点核对 → 时间修正 → 维护窗口排除 → 小时聚合与邻站诊断 → 完整性判定 → JSON/Markdown 水文报告。

脉冲用最近的有效校时锚点修正为 UTC；无锚点标记 `clock_anchor_missing`。锚点偏移差超过阈值为 `clock_drift`，不可假装可信。维护窗口采用 `[start,end)`；窗口内测试脉冲不计自然降水。小时桶在 UTC 半开区间聚合，再按站点时区标记。系数按生效时间选择（生效点含边界），缺失为 `coefficient_missing`；物理强度超限为 `physical_spike`，邻站差异为 `neighbor_disagreement`。设备断号、心跳缺失或间隔过大分别标记，形成 `trusted`、`incomplete`、`review` 结论。

## 小时可信区间

状态只说明不完整，无法回答“这一小时到底可能差多少”。导入阶段由 `sequence_inventory` 按设备把连续断号归并为一个未知脉冲块（块内脉冲数 = 缺失序号数），规则阶段对每个块联合时钟、维护、系数与速率约束求每小时 `[mm_lower, mm_upper]`：

- 时钟包络：断号前后可定位事件分别用最近锚点修正，再按 `max_clock_drift_seconds` 向两侧扩张，得到未知块可能落入的 UTC 半开窗口；无前置锚点时该块不可定位，触及小时标 `unbounded` 且不发布数值。
- 跨桶分配：包络在本地整点与维护边界处切段，每段映射到唯一站点本地小时；同一未知块在所有触及小时间统一分配，任何可行分配的脉冲总数恒等于块大小，跨小时不重复计数，也不按导入顺序或单一猜测时间归桶。
- 维护扣除：完全落在 `[start,end)` 维护窗内的段允许未知脉冲数为 0；整块都被维护覆盖时上下界均为 0，但断号问题仍保留。
- 系数与速率：每段按其本地小时的生效系数折算；每小时未知脉冲受 `max_mm_per_hour` 扣除实测与已预留量后的容量约束。每小时上界为 `min(容量, 块大小)`，下界为 `max(0, 块大小 − 其余小时容量之和)`；容量装不下整块时记 `physical_spike`。

值守员在同一引擎上选择发布策略。保守策略仅当小时上下界相等才发布数值，否则整小时 `review` 且不输出中点；区间策略发布 `[下界,上界]`，当区间完全处于站点调度阈值一侧时标记 `usable`，跨越阈值（或未配置阈值）时标记 `pending`。任何输出都不得把区间中点冒充实测：实测值单独存于 `measured_mm`，未知量存于 `unknown_mm_lower/upper`。

每条边界在 `bounds` 中留痕：缺口前后 event id、锚点与维护 event id、来源 source id、UTC 包络、逐段容量与系数、上下界脉冲合计，小时级再汇总支撑该小时的 event/source/evidence id。重算把上一版决策写入 `decision_history`，并在 `recompute_diff` 中逐小时给出新旧上下界与差值；输入不变时重算结果逐位复现。

导入为事务，重复文件不重写；身份碰撞留 `identity_conflict`。每次重算只更新业务问题和决策，源事件不可变。当前不做实时遥测、洪峰预警或区域面雨量估算。
